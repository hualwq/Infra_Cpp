## 第一部分：智能指针（Smart Pointer）

### 面试回答（精简版）

智能指针是 C++11 引入的 RAII 类模板，用来自动管理堆对象的生命周期，析构时自动 delete，避免内存泄漏。主要有三种：`unique_ptr`、`shared_ptr`、`weak_ptr`。

---

### 1. unique_ptr

**用途：**
独占所有权的智能指针。同一时刻只有一个 `unique_ptr` 指向对象，不能拷贝，只能通过 `std::move` 转移所有权。适合管理独占资源，比如工厂函数的返回值、容器中的独占元素。

**内存开销：**
零额外开销。对象本身只存一个裸指针，大小和 `T*` 一样，没有控制块，没有引用计数。编译器生成的代码和裸指针几乎完全相同。

**总结：** 能 `unique_ptr` 就优先用它，零开销、语义清晰。

---

### 2. shared_ptr

**用途：**
共享所有权的智能指针。多个 `shared_ptr` 可以指向同一个对象，通过引用计数管理生命周期。每次拷贝引用计数 +1，析构时 -1，归零时释放对象。适合多个模块需要共享同一对象的场景。

**内存开销：**
有额外开销。除了对象指针，还需要一个**控制块**（存放引用计数、删除器等），控制块是堆上分配的独立内存（如果用 `make_shared` 会和对象一起分配，减少一次分配但仍有控制块）。引用计数的修改是原子操作，有一定性能成本。

**总结：** 只在真正需要共享所有权时才用，开销比 `unique_ptr` 大。

---

### 3. weak_ptr

**用途：**
不拥有所有权的智能指针，从 `shared_ptr` 构造，不增加引用计数。不能直接访问对象，需要通过 `lock()` 获取 `shared_ptr` 后才能访问，`lock()` 返回空表示对象已释放。主要用于观察者模式、缓存、以及打破 `shared_ptr` 的循环引用。

**内存开销：**
和 `shared_ptr` 共享同一个控制块，本身只存一个弱引用计数，开销很小。但它指向的控制块只有在所有 `shared_ptr` 和 `weak_ptr` 都销毁后才会释放。

---

### 4. 循环引用与 weak_ptr 打破循环

**问题：**
如果两个类互相用 `shared_ptr` 持有对方，引用计数永远不会归零，导致内存泄漏。例如 `Parent` 持有 `shared_ptr<Child>`，`Child` 持有 `shared_ptr<Parent>`，两者都无法释放。

**解决：**
把其中一个的 `shared_ptr` 改为 `weak_ptr`。`weak_ptr` 不增加引用计数，因此不会阻止对方被释放。通常把"子对象"对"父对象"的引用改为 `weak_ptr`，因为父对象生命周期通常长于子对象。

**一句话：** `shared_ptr` 循环引用会导致内存泄漏，`weak_ptr` 不增加引用计数，用它来打破循环。

---

### 面试一句话总结

> `unique_ptr` 零开销、独占所有权，优先使用；`shared_ptr` 有引用计数开销，只在需要共享时用；`weak_ptr` 不拥有对象，专门用来打破 `shared_ptr` 的循环引用。

## 第二部分：类型转换（Type Cast）

### 面试回答（精简版）

C++ 提供了四种显式的类型转换操作符，比 C 风格的 `(type)` 转换更明确、更安全。编译器转换时只看**声明类型**，不知道运行时的**实际值**。

---

### 1. static_cast（静态转换）

**用途：**
最通用的转换。在编译期基于类型关系判断，无运行期开销。适用于基本类型转换（`int` ↔ `double`）、上行转换（子类 → 父类，安全）、下行转换（父类 → 子类，不安全）。也支持 `void*` 与具体类型指针之间的转换。

**不安全的原因：**
下行转换不安全不是转换过程的问题，而是转换后访问了不存在的成员。编译器只基于「声明类型」放行，但指针**实际指向什么**只有运行时才知道。如果父类指针实际指向的是父类对象，你却把它转成子类指针去访问子类特有的成员，就是未定义行为。

**安全的前提：**
绝对安全的下行转换只有一个条件——**父类指针实际指向的是子类对象**。`static_cast` 不检查这个条件，它相信程序员。

```cpp
int i = 42;
double d = static_cast<double>(i);          // 基本类型
Base* b = static_cast<Base*>(&derived);     // 上行转换，安全
Derived* d = static_cast<Derived*>(base);   // 下行转换，需保证base指向Derived
```

---

### 2. dynamic_cast（动态转换）

**用途：**
安全的下行转换。运行时通过 RTTI（虚函数表）检查指针/引用实际指向的对象类型。只能用于**含有虚函数的多态类型**。转换失败时：指针返回 `nullptr`，引用抛出 `std::bad_cast` 异常。

**与 static_cast 的区别：**
`static_cast` 相信程序员（前提不对就未定义行为），`dynamic_cast` 不相信程序员（前提不对就返回失败）。两者的安全前提相同——指针实际指向子类对象，但 `dynamic_cast` 在不满足前提时给你一个安全的失败方式。

```cpp
Base* p = new Base();
Derived* d1 = dynamic_cast<Derived*>(p);   // 失败，d1 == nullptr
Derived& d2 = dynamic_cast<Derived&>(*p);  // 失败，抛出 bad_cast

Base* p2 = new Derived();
Derived* d3 = dynamic_cast<Derived*>(p2);  // 成功
```

---

### 3. const_cast（常量转换）

**用途：**
添加或去除 `const`/`volatile` 属性。**唯一**能去除 `const` 的转换。只能作用于指针和引用，不能直接作用于对象。

**核心机制：**
`const_cast` 只是给你一个非 `const` 的钥匙，但你必须通过一个新的非 `const` 指针/变量去使用它，才能修改值。如果又把结果赋回 `const` 指针，等于白做。

**危险前提：**
如果原对象**本身就是 `const`**，去除 `const` 后修改是未定义行为。只有原对象本身非 `const`，只是通过 `const` 指针访问它时，去除 `const` 修改才是安全的。

```cpp
int x = 10;
const int* y = &x;
// y = const_cast<int*>(y);  // ❌ 赋回 const int*，白做

int* z = const_cast<int*>(y);   // ✅ 赋给新的 int*
*z = 20;                         // ✅ x 本身不是 const，安全

const int c = 10;
// *const_cast<int*>(&c) = 20;  // ❌ c 本身是 const，未定义行为
```

---

### 4. reinterpret_cast（重解释转换）

**用途：**
最危险的转换。只是重新解释内存的比特位，不做任何检查。用于任意指针类型互转、指针与整数互转、函数指针互转。结果依赖平台和编译器，不可移植。

```cpp
int intVal = 0x12345678;
char* cp = reinterpret_cast<char*>(&intVal);           // int* → char*
uintptr_t addr = reinterpret_cast<uintptr_t>(&intVal); // 指针 → 整数
int* ip = reinterpret_cast<int*>(addr);                // 整数 → 指针
```

---

### 总结对比

| 转换 | 检查时机 | 适用场景 | 不安全因素 |
|------|---------|---------|-----------|
| `static_cast` | 编译期 | 基本类型、确定的类型转换 | 下行转换安全由程序员保证 |
| `dynamic_cast` | 运行期 | 多态类型的下行转换（需要虚函数） | 失败返回 `nullptr`/异常，安全 |
| `const_cast` | 编译期 | 去除/添加 `const` | 原对象为 `const` 时修改是未定义行为 |
| `reinterpret_cast` | 编译期 | 低层比特位重解释 | 几乎所有使用都是危险的 |

## 第三部分：堆与栈的区别（Stack vs Heap）

| 维度 | 栈（Stack） | 堆（Heap） |
|------|-----------|-----------|
| **分配方式** | **自动分配**。函数内的局部变量直接在栈上分配，函数返回时自动回收，由编译器管理。 | **手动分配**。通过 `new`/`malloc` 分配，必须手动 `delete`/`free`，由程序员管理（或用智能指针自动管理）。 |
| **大小** | **小（约 1-8 MB）**。栈空间固定且有限，栈溢出常见于深层递归或分配大数组。 | **大（GB 级别）**。受限于系统可用内存，可以分配大对象和大数组。 |
| **效率** | **快**。分配就是移动栈顶指针（`sp += size`），一条 CPU 指令，没有复杂的数据结构。 | **慢**。分配需要在空闲块中搜索合适大小的区域，涉及内存管理算法（如空闲链表），多线程下还有锁竞争。 |
| **碎片** | **无碎片**。先入后出，分配和释放完全顺序，不会产生内存空洞。 | **有碎片**。分配和释放顺序不可控，小对象反复分配释放会产生外部碎片，导致大块分配失败。 |

### 一句话总结

> 栈快、自动、空间小、无碎片，适合局部小对象；堆慢、手动管理、空间大、有碎片，适合大对象或需要跨函数存活的对象。


## 第四部分： 构造函数和析构函数能是虚函数吗
1. 构造函数不能是虚函数，虚函数调用通过虚函数表，构造函数执行的时候，虚函数表还没有创建
2. 析构函数可以是虚函数，存在继承关系的时候，必须申明为虚函数，否则析构了父类，内存泄露。

## 第六部分： STL

### unordered_map 和 map
unordered_map 通过 hash table实现，查找最快O(1)，最坏O(n)，C++11引入

### vector

#### size() 和 capacity() 有什么区别？扩容的时候发生了什么？
当size() == capacity() 的时候触发，不同编译器增长倍率不同，总之是1.5或者2，迁移过程就是分配新空间，迁移元素并释放旧空间。

#### vector和array的区别
array在编译期确定大小，不可扩容，通常分配在栈上，vector分配在堆上，array和C++中的原生数组一样快，vector有分配开销，可能有扩容的拷贝

#### push_back() 和 emplace_back()
push_back() 构造一个对象，然后移动过去，emplace_back()就地构造一个对象，避免了临时对象的创建和移动

## 第七部分 C++基础

### C++从代码到可执行过程
预处理，编译，汇编，链接

### new和malloc的区别
malloc是纯内存分配器，只管要一块原始内存，new是对象生命周期管理，malloc是函数，new是操作符。new调用构造函数，delete调用析构函数，malloc/free不会。malloc需要指定大小，返回void*需要强转，new自动计算，返回对应类型指针。

### 静态链接和动态链接的区别
静态链接直接将代码嵌入可执行文件，动态链接在运行的时候链接，可执行文件中只包含重定位信息。

### 浅拷贝和深拷贝的区别
浅拷贝仅复制对象的指针，新旧对象共享一块内存，修改一个影响另一个，深拷贝重新分配内存并复制对象所有内容。拷贝构造函数是浅拷贝，对象动态分配内存的时候，可能导致重复释放。


### static的作用
1. 修饰全局变量/函数仅在本文件内可见
        限制作用域，使变量只在当前文件中使用

2. 修饰局部变量，静态变量存在于静态存储区，生命周期到程序结束

3. 默认初始化0
4. 类成员，这个变量属于类不属于类实例
5. 类函数，无this指针，只能访问静态成员
